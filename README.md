# Jiho Kim Skills

[andrej-karpathy-skills](https://github.com/forrestchang/andrej-karpathy-skills)와 같은 구조의 `CLAUDE.md` 하나.

한국어 | [English](./README.en.md)

## 왜 만들었나

AI를 많이 쓰는데 결과가 항상 좋지는 않다. 원인은 세 가지다.

- **주도권이 AI 쪽으로 넘어간다.** 확률 모델이라 AI가 방향을 쥐면 결과 품질이 매번 달라진다.
- **부분만 본다.** 지금 고치는 곳만 보다가 전체 맥락을 잃는다.
- **복잡도가 오른다.** 문제를 갈수록 복잡하게 풀고, 그러다 원래 풀려던 문제에서 멀어진다.

그래서 원칙은 셋이다: **방향은 사용자가 정한다. 전체 맥락을 지킨다. 복잡도는 예산이다.**

## 구성

**공통 원칙** (모든 작업)

| # | 규칙 | 막는 것 |
|---|---|---|
| 1 | 방향이 비어 있으면 끝까지 묻는다 | 추정으로 채운 빈 칸 |
| 2 | 사용자가 정하고, 전체 맥락을 지킨다 | 주도권 이동, 부분에 맞춰 바뀐 전체 |
| 3 | 복잡도는 예산이다 | 덧붙이기, 같은 문제에 시도만 쌓기 |
| 4 | 지적받으면 같은 패턴 전체를 찾는다 | 한 곳만 고치고 끝내기, 땜질 |
| 5 | 확인한 것만 완료라고 한다 | 말뿐인 "다 됐습니다" |

**대화할 때:** 쉬운 한국어, 객관식과 추천, 말보다 화면, 짧은 지시는 가장 좁게, 완료 보고 형식.

**개발할 때:** MECE 구조, 덧대지 않고 근본 설계를 지키는 코드, 옛 기능은 대체, 직접 확인, 배포와 git 안전.

전문은 [CLAUDE.md](./CLAUDE.md), 전/후 예시는 [EXAMPLES.md](./EXAMPLES.md).

## 근거

직접 쓴 세션 615개, 메시지 5,855개(2025-09-11 ~ 2025-10-23)를 전부 읽고 반복되는 요구를 정리했다.

- 메시지의 44%가 15자 이하다. 세션 37%(230개)는 "배포"류 한 단어로 일을 넘겼다. 규칙 1과 대화 규칙이 짧은 지시를 가장 좁게 읽게 한다.
- "기획 먼저"가 30개 세션 이상, 영어 답변에 대한 "한글"이 30개 세션 이상 나왔다.
- "좁게 해석하지 말고 전체 재검토"가 구간마다 8~11개 세션에 나왔다. 규칙 4.
- "확인했어?", "진짜야?"가 거의 모든 긴 세션에 나왔다. 규칙 5.
- 다시 작업의 가장 흔한 원인은 사용자가 기준을 늦게 말한 것이었다. 규칙 1이 AI 쪽에서 이 빈틈을 메운다.

## 카파시 지침과 다른 점

| 카파시 | 여기 |
|---|---|
| Think Before Coding | 규칙 1, 2. 가정을 말하는 데서 그치지 않고 빈 칸이 없어질 때까지 묻는다. 부분을 고쳐도 전체 맥락을 지킨다 |
| Simplicity First | 규칙 3과 개발 규칙. 같은 방향에 더해, 덧대지 않고 MECE 구조를 지킨다 |
| **Surgical Changes** | **규칙 4. 반대.** 지적 하나를 같은 패턴 전체로 넓힌다. 단 같은 문제만, 다른 문제는 보고만 |
| Goal-Driven Execution | 규칙 5. 실제 사용자처럼 써 보고, 완료 보고 형식을 고정한다 |

둘을 함께 설치하면 규칙 4가 충돌한다. 이쪽이 우선한다.

## 설치

Claude Code 플러그인:
```
/plugin marketplace add SteveKim0513/jiho-kim-skills
/plugin install jiho-kim-skills@jiho-kim-skills
```

플러그인은 설명문을 보고 Claude가 불러오는 방식이라 항상 적용되지는 않는다. 항상 적용하려면 `~/.claude/CLAUDE.md`에 [CLAUDE.md](./CLAUDE.md)를 붙인다.

```bash
curl https://raw.githubusercontent.com/SteveKim0513/jiho-kim-skills/main/CLAUDE.md >> ~/.claude/CLAUDE.md
```

Cursor는 `.cursor/rules/jiho-kim-guidelines.mdc`가 항상 적용된다. 다른 프로젝트에서 쓰는 법은 [CURSOR.md](./CURSOR.md).

## 파일

`CLAUDE.md`, `skills/jiho-kim-guidelines/SKILL.md`, `.cursor/rules/jiho-kim-guidelines.mdc`의 본문은 같아야 한다. 하나를 고치면 셋을 함께 고친다.
