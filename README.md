# Jiho Kim Skills

AI 에이전트와 일할 때 쓰는 행동 지침. `CLAUDE.md` 하나로 쓴다.

한국어 | [English](./README.en.md)

## 왜 만들었나

AI를 많이 쓰지만 결과가 항상 좋지는 않다. 원인은 세 가지다.

- **주도권이 AI 쪽으로 넘어간다.** 확률 모델이라 AI가 방향을 쥐면 결과 품질이 매번 달라진다.
- **부분만 본다.** 지금 고치는 곳만 보다가 전체 맥락을 잃는다.
- **복잡도가 오른다.** 문제를 덧붙여서 풀다가 원래 풀려던 문제에서 멀어진다.

그래서 원칙은 셋이다. **방향은 사용자가 정한다. 전체 맥락을 지킨다. 복잡도는 예산이다.**

## 지침 구성

지침은 표 하나다. 작업의 정해진 순간마다 예/아니오로 확인하고, 실패하면 정해진 행동을 먼저 한다. ★는 "예"가 실패다.

- **시작 전:** 목표, 완료 기준, 기준선, 범위가 비면 한 번에 하나씩 객관식으로 묻는다.
- **"진행해"를 들으면:** 합의된 다음 한 단계만 한다. 배포, 삭제, 결제, 발송은 이름으로 지시받았을 때만 한다.
- **되돌리기 어려운 일 전:** 바뀌는 것을 나열하고 먼저 묻는다.
- **바꾸기 전, 바꾼 뒤:** 앞서 정한 것이 유지되는지, 규칙·예외·코드 경로가 늘었는지 본다.
- **고침이 두 번 실패하면:** 멈추고 전제를 시험한다.
- **지적받은 뒤:** 같은 패턴을 전부 찾고 근본을 고친다. 같은 문제만 고치고 다른 문제는 보고만 한다.
- **코드를 쓸 때:** 한 사실에 주인 하나, 역할은 MECE, 새 기능은 제자리에. 덧대지 않는다.
- **끝내기 전:** 직접 확인한 것만 완료라고 하고, 확인 못 한 것은 따로 쓴다. 쉬운 말로 답한다.

전문은 [CLAUDE.md](./CLAUDE.md).

## 검증

Claude Code를 격리된 폴더에서 약 1,900번 헤드리스로 돌려 지침이 있을 때와 없을 때를 비교했다. 모델은 Sonnet 5.5, 프롬프트는 한국어, 저장소는 작은 모의 프로젝트다.

| 상황 | 지침 없음 | 이 지침 |
|---|---|---|
| 모호한 요청에서 만들지 않고 묻는다 | 0/20 | 20/20 |
| "진행해"에서 한 단계에서 멈춘다 | 0/20 | 20/20 |
| 모호한 "정리해줘"에서 확인 없이 지우지 않는다 | 3/20 | 20/20 |

명확한 작업에서는 괜히 되묻지 않았고(60건 중 0~1건) 결과도 그대로였다. 근본 원인 수정, 같은 패턴 전체 수정, 테스트 실행, 정직한 완료 보고는 지침 없이도 이미 거의 100%여서 개선 여지가 없었다. 쉬운 설명과 "관련 없는 문제는 보고만"은 뚜렷한 효과가 없었다.

## 출처

실제 AI 작업 세션 600여 개에서 사용자가 반복해 요구한 것과, 실제 프로젝트의 작업 가이드를 일반화했다.

## 설치

Claude Code 플러그인:
```
/plugin marketplace add SteveKim0513/jiho-kim-skills
/plugin install jiho-kim-skills@jiho-kim-skills
```

플러그인 스킬은 Claude가 설명문을 보고 불러오는 방식이다. 시험에서는 거의 매번 불러왔지만 보장은 아니다. 항상 적용하려면 `CLAUDE.md`를 프로젝트에 두거나 `~/.claude/CLAUDE.md`에 붙인다.

```bash
curl https://raw.githubusercontent.com/SteveKim0513/jiho-kim-skills/main/CLAUDE.md >> ~/.claude/CLAUDE.md
```

## 요청하는 사람을 위한 틀

원칙 1은 AI가 빈 칸을 묻게 하지만, 첫 메시지에 직접 주면 더 빠르다.

```
목표: (한 문장)
완료 기준: (확인할 수 있는 한 문장)
기준선: (맞출 기존 결과물, 없으면 "없음")
범위: (어디까지 할지. 예: 로컬 확인까지 / PR까지 / 배포까지)
```
